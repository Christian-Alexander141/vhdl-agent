⚙️ Vivado Startprobleme & Lösung

Problem: Vivado startet nicht aus dem Startmenü

Nach der Installation von Vivado 2026.1 konnte das Programm nicht über das Startmenü gestartet werden. Der Menüeintrag existierte, aber der Klick hatte keine Wirkung.

🔍 Fehleranalyse: Vivado benötigt spezifische Bibliotheken, die sich in /home/alex/Xilinx/2026.1/Vivado/lib/lnx64.o/Ubuntu/24/ befinden. Diese wurden nicht automatisch in den Library Path aufgenommen.

Lösung: LD_LIBRARY_PATH in .desktop-Datei anpassen

1

Aktuellen Inhalt der .desktop-Datei prüfen

Die Originaldatei enthielt:

[Desktop Entry]
Encoding=UTF-8
Type=Application
Name=Vivado 2026.1
Comment=Vivado 2026.1
Icon=/home/alex/Xilinx/2026.1/Vivado/doc/images/vivado_logo.png
Exec=/home/alex/Xilinx/2026.1/Vivado/bin/vivado
2

.desktop-Datei bearbeiten

Die Exec-Zeile wurde angepasst, um die Umgebungsvariable LD_LIBRARY_PATH zu setzen:

Exec=env LD_LIBRARY_PATH=/home/alex/Xilinx/2026.1/Vivado/lib/lnx64.o/Ubuntu/24:$LD_LIBRARY_PATH /home/alex/Xilinx/2026.1/Vivado/bin/vivado

Befehl zum Bearbeiten:

nano "/home/alex/.local/share/applications/Vivado 2026.1_1787339248861.desktop"

Speichern: STRG + O → Enter → STRG + X

3

Menü aktualisieren

Nach dem Speichern der Änderungen:

  • Normalerweise erkennt Linux Mint die Änderung automatisch
  • Falls nicht: Ab- und wieder anmelden
  • Alternativ: update-desktop-database ~/.local/share/applications/
✅ Ergebnis: Vivado 2026.1 startet nun erfolgreich über das Startmenü.

🔍 Warum war diese Änderung notwendig?

Vivado ist eine komplexe Anwendung, die auf viele dynamische Bibliotheken (.so-Dateien) zugreift. Unter Linux werden diese Bibliotheken über die Umgebungsvariable LD_LIBRARY_PATH gefunden.

Xilinx installiert seine Bibliotheken in einem spezifischen Verzeichnis (lnx64.o/Ubuntu/24/), das nicht standardmäßig in der Suchpfad für Bibliotheken enthalten ist. Durch das Setzen von LD_LIBRARY_PATH vor dem Start von Vivado wird dieses Verzeichnis in den Suchpfad aufgenommen.

📚 Weiterführende Informationen zu LD_LIBRARY_PATH

Die LD_LIBRARY_PATH ist eine Umgebungsvariable unter Unix-ähnlichen Systemen, die den Lader anweist, wo er nach Shared Libraries suchen soll.

Linux man-pages: ld.so(8) - Dynamic linker/loader TLDP: Shared Libraries HOWTO

📥 Digilent Board Files installieren

Problem: Arty S7-50 nicht in der Board-Liste

Bei der Projekterstellung in Vivado wurde das Arty S7-50 Board nicht in der Board-Liste angezeigt. Stattdessen wurden nur generische FPGA-Parts wie xc7s50csga324-1 angezeigt.

💡 Hintergrund: Vivado kennt zwar die Spartan-7 FPGA-Familie, aber ohne die spezifischen Board Files von Digilent fehlen:
  • Board-spezifische Pin-Belegungen
  • Vorgefertigte Constraints
  • Board-spezifische IP-Cores
  • Einfache Board-Auswahl statt manueller Part-Auswahl

Lösung 1: Board Files über Vivado Refresh herunterladen (empfohlen)

1

Projekt-Erstellung starten

In Vivado: Create Project → Next

2

Board-Auswahl öffnen

Im Fenster Default Part zum Reiter Boards wechseln.

3

Refresh-Button klicken

Unten links im Fenster befindet sich ein blauer Kreispfeil (↻). Auf diesen klicken, um die Board-Dateien aus dem Git-Repository herunterzuladen.

📝 Hinweis: Vivado zeigt oben den Hinweis: "To fetch the latest available boards from git repository, click on 'Refresh' button."
4

Arty S7-50 auswählen

Nach dem Refresh im Suchfeld Arty S7 eingeben. Das Board sollte nun angezeigt werden:

  • Vendor: Digilent
  • Display Name: Arty S7-50
  • Part: xc7s50csga324-1

Lösung 2: Manuelle Installation der Board Files (Fallback)

Falls der Refresh-Button nicht funktioniert, können die Board Files manuell installiert werden.

1

Repository klonen

git clone https://github.com/Digilent/vivado-boards.git cd vivado-boards
2

Board Files kopieren

Die Board Files müssen in das Vivado-Board-Verzeichnis kopiert werden:

# Standardpfad für Vivado Board Files BOARD_DIR="/home/alex/Xilinx/2026.1/Vivado/data/boards/board_files" # Board Files kopieren sudo cp -r new/board_files/* "$BOARD_DIR/"
3

Vivado neustarten

Nach der Installation Vivado neu starten. Das Arty S7-50 sollte nun in der Board-Liste angezeigt werden.

✅ Ergebnis: Das Arty S7-50 Board wird nun in Vivado erkannt und kann für neue Projekte ausgewählt werden.

🔍 Warum sind Board Files notwendig?

FPGA-Boards wie das Arty S7-50 haben spezifische Hardware-Konfigurationen:

  • Pin-Belegung: Welche Pins des FPGA mit welchen Board-Komponenten (LEDs, Schalter, USB, etc.) verbunden sind
  • Constraints: Timing- und Platzierungs-Constraints für optimale Performance
  • IP-Cores: Vorgefertigte IP-Blöcke für Board-spezifische Komponenten (z.B. USB-PHY)
  • Board-Definition: Automatische Erkennung von Board-Features

Ohne diese Informationen müsste man alle Pin-Belegungen manuell definieren, was fehleranfällig und zeitaufwendig ist.

🔬 Technische Erklärungen

1. Warum LD_LIBRARY_PATH für Vivado?

Vivado besteht aus Hunderten von Shared Libraries (.so-Dateien), die in verschiedenen Verzeichnissen liegen:

  • /home/alex/Xilinx/2026.1/Vivado/lib/lnx64.o/ - Hauptbibliotheken
  • /home/alex/Xilinx/2026.1/Vivado/lib/lnx64.o/Ubuntu/24/ - Ubuntu 24-spezifische Bibliotheken
  • /home/alex/Xilinx/2026.1/Vivado/lib/lnx64.o/Default/ - Standard-Bibliotheken

Der Linux Dynamic Linker (ld.so) sucht standardmäßig in:

  • /lib
  • /usr/lib
  • /lib64
  • /usr/lib64
  • Pfade in /etc/ld.so.conf

Da die Xilinx-Bibliotheken in einem benutzerdefinierten Pfad liegen, müssen wir diesen explizit angeben.

# Anzeigen der aktuellen LD_LIBRARY_PATH echo $LD_LIBRARY_PATH # Anzeigen der von Vivado benötigten Bibliotheken ldd /home/alex/Xilinx/2026.1/Vivado/bin/vivado | head -20

2. Warum Board Files statt generischer Parts?

Ein FPGA-Board ist mehr als nur der FPGA-Chip. Das Arty S7-50 enthält:

  • FPGA: XC7S50CSGA324-1 (Spartan-7)
  • Speicher: 512 MB DDR3L
  • Flash: 16 MB Quad-SPI Flash
  • USB: USB-JTAG für Programmierung und Debugging
  • LEDs: 4x Benutzer-LEDs, 2x RGB-LEDs
  • Schalter: 4x Dip-Schalter, 4x Drucktaster
  • UART: USB-UART Bridge (FT2232H)
  • Pmod: 4x Pmod-Ports (2x 6-Pin, 2x 12-Pin)
  • Arduino: Arduino-compatible Header
  • Clock: 100 MHz System-Clock

Die Board Files enthalten die genaue Pin-Belegung für all diese Komponenten, sodass Vivado automatisch weiß, welche FPGA-Pins mit welchen Board-Features verbunden sind.

3. Unterschied zwischen Part und Board in Vivado

Aspekt Part (z.B. xc7s50csga324-1) Board (z.B. Arty S7-50)
Definition Nur der FPGA-Chip Komplettes Board mit FPGA und Peripherie
Pin-Belegung Manuell definieren Automatisch vordefiniert
Constraints Manuell erstellen Board-spezifische Constraints enthalten
IP-Cores Generische IP-Cores Board-spezifische IP-Cores verfügbar
Einfachheit ❌ Komplexer ✅ Einfacher

4. Vivado Projekt-Struktur

Ein Vivado RTL-Projekt hat folgende Struktur:

ArtyS7_Test/ ├── ArtyS7_Test.srcs/ │ ├── sources_1/ │ │ └── new/ # Hier kommen Verilog/VHDL-Dateien hin │ └── constrs_1/ │ └── new/ # Hier kommen Constraint-Dateien (.xdc) hin ├── ArtyS7_Test.sim/ │ └── sim_1/ │ └── new/ # Hier kommen Testbench-Dateien hin └── ArtyS7_Test.xpr # Projekt-Datei

⚠️ Troubleshooting

Häufige Probleme & Lösungen

Problem: Vivado startet nicht nach .desktop-Änderung

Symptome: Menüeintrag existiert, aber nichts passiert beim Klicken.

Lösungen:

  1. Prüfen, ob die .desktop-Datei korrekt gespeichert wurde
  2. Menü-Cache aktualisieren: update-desktop-database ~/.local/share/applications/
  3. Ab- und wieder anmelden
  4. Rechner neustarten
  5. Manuell testen: env LD_LIBRARY_PATH=/home/alex/Xilinx/2026.1/Vivado/lib/lnx64.o/Ubuntu/24:$LD_LIBRARY_PATH /home/alex/Xilinx/2026.1/Vivado/bin/vivado

Problem: Arty S7-50 wird nicht erkannt (USB)

Symptome: Board wird nicht in Vivado angezeigt, obwohl Board Files installiert sind.

Lösungen:

  1. Prüfen, ob das USB-Kabel ein Datenkabel ist (kein reines Ladekabel)
  2. Prüfen, ob die LEDs auf dem Board leuchten (Stromversorgung)
  3. USB-Gerät prüfen: lsusb | grep -i digilent
  4. JTAG-Treiber prüfen: ls /dev/ttyUSB* oder ls /dev/ttyACM*
  5. Board neu anschließen (USB-Kabel abziehen und wieder anstecken)
  6. Vivado neu starten

Problem: Board Files werden nicht geladen

Symptome: Refresh-Button in Vivado funktioniert nicht.

Lösungen:

  1. Internetverbindung prüfen
  2. Proxy-Einstellungen prüfen (falls in einem Firmennetzwerk)
  3. Manuelle Installation der Board Files (siehe Abschnitt Board Files installieren)
  4. Vivado als Root starten (nur für Testzwecke): sudo vivado

Problem: Synthese fehlgeschlagen

Symptome: Fehler bei der Synthese des Verilog-Codes.

Lösungen:

  1. Fehlermeldung genau lesen und verstehen
  2. Syntax des Verilog-Codes prüfen
  3. Module korrekt instanziieren
  4. Alle Signale deklarieren
  5. Einfaches Design testen (z.B. nur eine LED ansteuern)

Problem: Programmierung fehlgeschlagen

Symptome: Bitstream kann nicht auf das FPGA geladen werden.

Lösungen:

  1. Prüfen, ob das Board erkannt wird: vivado -mode batch -source tcl_commands.tcl
  2. JTAG-Kette prüfen: In Vivado Hardware Manager → Open Target → Auto Connect
  3. Board neu anschließen
  4. Anderes USB-Kabel testen
  5. Anderen USB-Port testen

Diagnose-Befehle

# Vivado Version prüfen /home/alex/Xilinx/2026.1/Vivado/bin/vivado -version # USB-Geräte auflisten lsusb # Digilent-Geräte suchen lsusb | grep -i digilent # JTAG-Geräte prüfen dmesg | grep -i jtag dmesg | grep -i ftdi # Board Files Verzeichnis prüfen ls /home/alex/Xilinx/2026.1/Vivado/data/boards/board_files/ | grep -i arty # LD_LIBRARY_PATH prüfen echo $LD_LIBRARY_PATH # Vivado Bibliotheken prüfen ldd /home/alex/Xilinx/2026.1/Vivado/bin/vivado | grep "not found"

🎯 Nächste Schritte: LED-Blink-Test

Nach der erfolgreichen Einrichtung von Vivado und der Erkennung des Arty S7-50 Boards ist der nächste logische Schritt, einen einfachen Test durchzuführen: Eine LED zum Blinken bringen.

💡 Warum ein LED-Blink-Test?
  • Verifiziert, dass Vivado korrekt funktioniert
  • Bestätigt, dass das Arty S7-50 Board erkannt wird
  • Testet die USB/JTAG-Verbindung
  • Überprüft die Bitstream-Erzeugung
  • Validiert die FPGA-Programmierung
  • Gibt sofortige visuelle Rückmeldung

Vorbereitung für den LED-Blink-Test

1

Board anschließen

  • Micro-USB-Kabel an den PROG-Port des Arty S7-50 anschließen
  • Anderes Ende mit dem PC verbinden
  • Prüfen, dass die Power-LED (D1) leuchtet
2

Projekt öffnen

  • Vivado über das Startmenü öffnen
  • Das zuvor erstellte Projekt ArtyS7_Test öffnen
3

Verilog-Datei erstellen

Eine neue Verilog-Datei für den LED-Blinker erstellen:

  1. Rechtsklick auf Design Sources → Add or create design sources
  2. Create File auswählen
  3. Dateiname: led_blink.v
  4. Sprache: Verilog
4

Verilog-Code für LED-Blinker

Folgenden Code in die led_blink.v Datei einfügen:

// LED Blinker für Arty S7-50 // Blinkt mit LED0 (D4) mit ca. 1 Hz module led_blink ( input wire clk_100mhz, // 100 MHz System-Clock output reg led // LED0 (Pin D4 auf dem Arty S7-50) ); // 25-Bit Zähler für ca. 1 Hz Blinkfrequenz // 100 MHz / (2^25) ≈ 2.98 Hz → ca. 0.5 Hz Blinken reg [24:0] counter; always @(posedge clk_100mhz) begin counter <= counter + 1; // Bei Überlauf LED umschalten if (counter == 25'd33333333) begin led <= ~led; counter <= 0; end end endmodule
5

Constraints-Datei erstellen

Eine XDC-Datei für die Pin-Belegung erstellen:

  1. Rechtsklick auf Constraints → Add or create constraints
  2. Create File auswählen
  3. Dateiname: arty_s7_50_led.xdc

Folgenden Inhalt einfügen:

# Arty S7-50 LED Constraints # LED0 ist mit FPGA Pin D4 verbunden # LED Pins (Arty S7-50) set_property PACKAGE_PIN D4 [get_ports led] set_property IOSTANDARD LVCMOS33 [get_ports led] # Clock Pin (100 MHz System-Clock) set_property PACKAGE_PIN E3 [get_ports clk_100mhz] set_property IOSTANDARD LVCMOS33 [get_ports clk_100mhz] # Clock Period Constraint create_clock -add -name sys_clk_pin -period 10.00 -waveform {0 5} [get_ports clk_100mhz]
6

Design synthetisieren & implementieren

  1. Run Synthesis klicken
  2. Nach erfolgreicher Synthese: Run Implementation klicken
  3. Nach erfolgreicher Implementierung: Generate Bitstream klicken
7

Bitstream auf das FPGA programmieren

  1. Open Hardware Manager klicken (oder Program and Debug)
  2. Open Target → Auto Connect
  3. Das Arty S7-50 Board sollte angezeigt werden
  4. Rechtsklick auf das Board → Program Device...
  5. Die generierte Bitstream-Datei auswählen und programmieren
8

Test durchführen

Nach erfolgreicher Programmierung:

  • Die LED D4 auf dem Arty S7-50 sollte nun mit ca. 0.5 Hz blinken
  • Falls nicht: Troubleshooting (siehe Abschnitt Troubleshooting)
✅ Erfolg! Wenn die LED blinkt, funktioniert dein Vivado-Setup mit dem Arty S7-50 Board einwandfrei! 🎉
