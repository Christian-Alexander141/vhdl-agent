# Projektbeschreibung: KI-gestützte Engineering-Agentenplattform

## Ziel

Entwickle eine modulare KI-Agentenplattform, die über ein Dashboard und einen Chat bedient wird.

Der Benutzer beschreibt eine technische Aufgabe in natürlicher Sprache. Der Agent analysiert die Aufgabe, nutzt domänenspezifisches Wissen über eine RAG-Komponente, erzeugt Dateien und kann komplexe Entwicklungsaufgaben an einen spezialisierten Coding-Agenten (OpenCode) delegieren.

Das System soll zunächst für Hardwareentwicklung mit VHDL ausgelegt werden, aber später auf andere technische Domänen erweiterbar sein.

Beispiel:

Benutzer:
"Erzeuge einen 8-Bit-Zähler in VHDL mit Testbench."

System:

1. Analysiert die Anforderungen.
2. Nutzt RAG mit internen VHDL-Standards und Beispielen.
3. Erzeugt:

   * counter.vhd
   * counter_tb.vhd
4. Speichert die Dateien in einem isolierten Workspace.
5. Übergibt die Aufgabe an OpenCode.
6. OpenCode führt Tests mit GHDL aus.
7. Bei Fehlern analysiert OpenCode die Fehler, verbessert den Code und testet erneut.
8. Das Ergebnis wird an den Chat und das Dashboard zurückgegeben.

---

# Architekturprinzip

Das System soll NICHT als freier Chat-Agent gebaut werden.

Der Kern ist ein Workflow-Orchestrator.

Das LLM entscheidet nicht alleine über alle Aktionen.

Der Orchestrator verwaltet:

* Zustand
* Aufgabenfortschritt
* Tool-Aufrufe
* Fehlerbehandlung
* Events für das Dashboard

---

# Hauptkomponenten

## 1. Dashboard

Aufgaben:

* Chat mit dem Agenten
* Anzeige des Agentenstatus
* Visualisierung des Workflows
* Anzeige von Logs
* Anzeige von erzeugten Dateien
* Anzeige von Testergebnissen

Das Dashboard kommuniziert mit dem Backend über API/WebSocket.

---

# 2. Orchestrator

Der Orchestrator ist die zentrale Komponente.

Verantwortlichkeiten:

* Erzeugen einer Task-ID
* Verwalten des Zustands
* Ausführen der Workflow-Schritte
* Aufrufen der Services
* Erzeugen von Events
* Fehlerbehandlung

Beispiel Workflow:

```
CREATED

↓

ANALYZING

↓

RAG_GENERATING

↓

FILES_CREATED

↓

TESTING

↓

REPAIRING

↓

COMPLETED
```

Der Orchestrator soll keine konkrete Implementierung von RAG oder OpenCode kennen.

Er arbeitet nur gegen Service-Schnittstellen.

---

# 3. Agent State

Der Zustand einer Aufgabe muss gespeichert werden.

Beispiel:

```python
{
    "task_id": "uuid",
    "status": "TESTING",
    "user_request": "...",
    "workspace": "./workspace/task123",
    "generated_files": [
        "counter.vhd",
        "counter_tb.vhd"
    ],
    "test_results": {},
    "history": []
}
```

---

# 4. Event System

Jede wichtige Aktion erzeugt ein Event.

Beispiele:

```
TASK_CREATED

RAG_STARTED

FILES_GENERATED

OPENCODE_STARTED

TEST_RUNNING

ERROR_FOUND

REPAIR_STARTED

TASK_COMPLETED
```

Events werden später an das Dashboard übertragen.

---

# 5. LLM Service

Der LLM-Service kapselt das Sprachmodell.

Verwendetes Modell:

GPT-OSS 120B über Ollama.

Aufgaben:

* Analyse von Benutzeranforderungen
* Zusammenfassung von Ergebnissen
* Kommunikation mit Benutzer

Das LLM soll NICHT direkt unkontrolliert Tools ausführen.

---

# 6. RAG Service

Der RAG-Service stellt technisches Wissen bereit.

Aufgaben:

* Suche in Wissensdatenbank
* Bereitstellung von Referenzdesigns
* Bereitstellung von Coding-Standards
* Unterstützung bei Codegenerierung

Schnittstelle:

```python
class RAGService:

    def generate_artifacts(
        self,
        request:str
    ) -> dict:
        pass
```

Beispiel Rückgabe:

```python
{
    "files": [
        {
            "name":"counter.vhd",
            "content":"..."
        },
        {
            "name":"counter_tb.vhd",
            "content":"..."
        }
    ]
}
```

---

# 7. Filesystem Service

Verantwortlich für:

* Workspace erzeugen
* Dateien speichern
* Dateien lesen
* Dateien verwalten

Regeln:

* Jede Aufgabe bekommt eigenen Workspace.
* Keine globalen Schreibrechte.

Beispiel:

```
workspace/

    task_001/

        src/

        tests/

        logs/
```

---

# 8. OpenCode Service

OpenCode wird als spezialisierter Entwicklungsagent verwendet.

Nicht für einfache Dateioperationen.

OpenCode Aufgaben:

* Projektanalyse
* Kompilieren
* Testen
* Debugging
* Refactoring

Beispiel Auftrag:

```
Arbeite im Workspace.

Führe VHDL Tests aus.

Verwende:

ghdl -a
ghdl -e
ghdl -r

Analysiere Fehler.

Verbessere den Code.

Wiederhole maximal fünf Iterationen.

Erstelle einen Bericht.
```

OpenCode läuft später isoliert:

* Container
* eingeschränkte Rechte
* Logging

# Technische Anforderungen

* Python 3.11+
* modulare Architektur
* klare Interfaces
* Logging
* Fehlerbehandlung
* Erweiterbarkeit
* keine harte Kopplung zwischen Komponenten

---

# Wichtig

Das System soll langfristig eine Plattform für technische KI-Agenten werden.

VHDL ist nur der erste Anwendungsfall.

Die Architektur muss später unterstützen:

* FPGA Entwicklung
* Embedded Software
* Python-Projekte
* Simulationen
* Dokumentation
* automatisierte Tests

Der Fokus liegt auf einem sicheren, nachvollziehbaren und erweiterbaren Agenten-Workflow.
